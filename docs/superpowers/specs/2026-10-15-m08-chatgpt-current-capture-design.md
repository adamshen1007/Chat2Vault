# M08 ChatGPT Current-Capture Design

Status: Product Owner-approved design; M08 implementation authorized on 2026-10-15; Task 3 temporary-artifact/threat-model and content-free reconciliation-ledger amendments approved on 2026-10-16; publication remains unauthorized
Date: 2026-10-15
Baseline: M07 merge on `main`, commit `932405219febc50e169ce364214f0b4de5cee488`
Scope: macOS desktop x86_64, matching the currently qualified plugin boundary

## 1. Purpose and decision

M08 reduces friction when a user wants to preserve text visible in a current ChatGPT web conversation. It does **not** claim to reconstruct a complete, export-equivalent conversation from a web page. The Product Owner selected ChatGPT first, deferred other AI chat sites, approved an official Obsidian Web Clipper companion with manual fallback, and accepted source preservation without web-capture distillation in M08.

The first approach is an importable template for the official Obsidian Web Clipper. The template creates a new staging note after the user's explicit **Add to Obsidian** action. Chat2Vault then previews an explicitly selected staging note and, after a separate user action, preserves a distinct create-only capture source note. Manual paste uses the same preview and save boundary when the browser page cannot be clipped satisfactorily. The documented [template behavior](https://obsidian.md/help/web-clipper/templates), [capture behavior](https://obsidian.md/help/web-clipper/capture), and [page variables](https://obsidian.md/help/web-clipper/variables) are design inputs, not proof that ChatGPT's full transcript is extractable.

This design follows [the roadmap](../../05_ROADMAP.md), [product brief](../../01_PRODUCT_BRIEF.md), [architecture](../../03_ARCHITECTURE.md), and `AGENTS.md`. The Product Owner separately authorized M08 implementation; this design does not authorize commit, push, merge, release, or provider spend.

## 2. Alternatives and scope

1. **Chosen: Web Clipper staging plus manual fallback.** Reuses an official browser extension and keeps Chat2Vault out of browser sessions. It needs a carefully bounded staging-note parser and a real compatibility test because page extraction may be incomplete.
2. **Manual paste only.** Has the smallest browser surface but retains more capture friction and does not fulfill the roadmap's preferred first approach.
3. **Custom Chat2Vault browser extension or Web Clipper fork.** Could control page extraction more closely but adds browser maintenance, account-page coupling, and a larger security surface without a validated gap. It is out of scope.

M08 is ChatGPT-only. No other AI chat website, ChatGPT credential/session access, hidden page data, browser automation, background capture, Web Clipper Interpreter, automatic knowledge extraction, M09 batch migration, or M10 release work is included. Existing export ZIP/JSON import remains unchanged.

## 3. Trust and data model

The browser page, clipped Markdown, staging-note properties, URL, title, and manually pasted text are untrusted. The Web Clipper note is **staging input**, not a Chat2Vault-owned source or knowledge note. The template must use **Create a new note**, never append/prepend to an existing note or a daily note, and must not use Interpreter or prompt variables. Its strict staging frontmatter contains `chat2vault_capture: 1`, `capture_method: "obsidian-web-clipper"`, `capture_scope: "visible-page-unverified"`, `source_provider: "chatgpt"`, `source_url`, and an optional `capture_title`; the remaining Markdown body is captured text. Duplicate, unknown, or malformed identity fields are rejected rather than guessed. The template may show a capture time, but it is not an identity or authority field. Its location is a user-selected staging folder separate from the configured Chat2Vault source and knowledge roots. The user sees and confirms the target vault/folder in Web Clipper before adding it.

Chat2Vault must not parse staging text as a ChatGPT export graph or manufacture message roles, IDs, chronology, hidden turns, or completeness. In memory, a capture draft holds the validated method, normalized source URL if available, sanitized display title, bounded text, content fingerprint, and `visible-page-unverified` scope. A manual-paste draft may omit the URL, in which case the preview prominently says that no provider-page URL will be preserved. A URL is provenance supplied by the capture workflow, not proof that the text came from or fully represents that page.

The saved artifact is a new **capture-source subtype**, not the M03 `ai-conversation-source` export subtype. Its frontmatter uses `chat2vault_schema: 2`, `type: "ai-conversation-web-capture"`, `source_provider: "chatgpt"`, `capture_method: "obsidian-web-clipper" | "manual-paste"`, `capture_scope: "visible-page-unverified"`, `capture_content_fingerprint: "sha256:<64 lowercase hex>"`, and an optional normalized `source_url`. It renders the captured text inertly in Markdown. The note must identify itself as a page/text capture and warn that selection, lazy loading, collapsed turns, and site changes may omit content. It must never say “complete conversation” or use export-only message/topology fields. The M03 export registry must explicitly distinguish valid capture-source notes from malformed export-source notes so their coexistence under the source root does not block either writer; malformed Chat2Vault-like notes still fail closed for the relevant flow. Capture-source notes are excluded from M04/M05/M06 distillation and knowledge-writing eligibility in M08. M07 knowledge matching must not mistake them for existing knowledge notes.

The fingerprint is SHA-256 over five ordered UTF-8 fields: `m08-capture-v1`, capture method, URL presence (`url` or `absent`), normalized URL (empty when absent), and normalized capture text. Each field is framed by its UTF-8 byte length as shortest-form ASCII decimal, then `:`, then those exact bytes; concatenate the five frames before hashing. Capture time and display title are excluded. Repeating the same method, URL, and text is a registry-level duplicate/no-write result; changed text produces a new immutable capture source. Different methods do not silently collapse into one provenance claim. Normalization is deterministic: reject invalid Unicode and NUL, remove one leading UTF-8 BOM if present, convert CRLF/CR to LF, and otherwise preserve text, including whitespace. Text must be nonempty and at most 1,048,576 UTF-8 bytes after normalization; the complete staging note is bounded at 1,064,960 bytes. URL input is bounded at 2,048 UTF-8 bytes. The planned source filename uses the existing safe-title policy plus a 12-hex-character fingerprint suffix; collisions extend the suffix or fail closed under the M03 path policy. Core test vectors must lock normalization, hash, filename, and render bytes before implementation is accepted.

## 4. User flow and components

1. The user opens a ChatGPT conversation in a supported desktop browser, invokes the official Web Clipper, inspects the proposed note content, vault, and staging folder, then explicitly adds a new staging note. The companion template is restricted to ChatGPT conversation URLs. It must not trigger on unrelated sites or silently clip in the background.
2. The user opens that staging note in Obsidian and invokes **Preview ChatGPT capture**. The plugin reads the active note through a bounded, physically contained vault adapter; it accepts only the closed staging marker and supported metadata, validates the URL when present, and shows captured text, byte count, origin label, scope warning, and proposed immutable source target. It does not automatically scan a folder or save the capture.
3. Alternatively, the user invokes **Paste ChatGPT capture**, enters text and optionally the page URL, and gets the same local preview. The plugin does not read the system clipboard automatically. Manual text remains memory-only until the explicit source save.
4. **Save capture source** requires a configured source root, a current exact preview, and explicit user activation. It re-reads and revalidates the staging note if that was the input, checks root/collision/physical-containment authority, and uses the M03 create-only, exact-byte readback, and conflict/no-op principles. It never modifies, deletes, renames, or consumes the staging note. After success, it opens or links the saved capture source note and reports the result without claiming extraction or distillation.

The Product Owner's Task 3 amendment permits a private, operation-owned, uncommitted temporary artifact for safe preparation of the exact source bytes. The capture path may remove **only that identified temporary artifact** before publication or after a failed attempt; it may not remove, rewrite, or rename staging notes, existing source/knowledge notes, or any published capture source. Publication must be exclusive and no-replace, with exact-byte readback. If publication or cleanup has an uncertain outcome, report a non-success state that requires reconciliation; never delete a possibly published source note to make a retry convenient. The temporary artifact must not be exposed as a capture source or intentionally included in source registries.

The Product Owner also selected Option A for a narrowly scoped, durable, content-free reconciliation record in plugin settings. This is the sole additional Chat2Vault write outside the private temporary artifact and explicit source target. It may contain only transaction state and the minimum opaque target/temporary identity needed to reconcile an uncertain effect; a title-bearing target pathname must not be stored verbatim. It must not contain captured text, conversation titles, source URLs, credentials, or private diagnostic content. The record must be durably prepared **before** exclusive publication, and the capture service—not only the current view—must refuse another capture write while an unresolved record exists, including after view reconstruction and plugin reload. Persistence failure fails closed. Only explicit acknowledgment after independently checking the filesystem outcome may clear the block; neither closing a view nor restarting the plugin clears it. A pre-publication failure with no possible published source may distinguish private-residue reconciliation from uncertain source publication, but neither may be silently forgotten.

The confinement guarantee covers ordinary path races, symlinks, stale queued authority, target collisions, and detectable root/parent identity changes. The native operation must bind its approved vault, source-parent, and relevant configuration identities at preview and recheck them at execution checkpoints; a queued root replacement must not redirect an authorized write. A hostile local actor with permission to **concurrently relocate an already-open vault/source directory hierarchy** is outside an absolute no-transient-bytes-outside-vault guarantee. This exception does not permit a false success: detectable relocation must fail closed, and residual temporary artifacts or uncertain external effects must be reported for human reconciliation. Tests must exercise queued replacement, mid-operation relocation, partial-write/failure cleanup, and exclusive-publication collisions. This is a bounded macOS-local threat model, not a claim of OS-enforced containment against an adversary controlling the directory hierarchy.

For the Task 3 ownership remediation, the uncommitted artifact is an exclusive 0600 regular file created directly relative to the already validated source-parent descriptor; the returned file descriptor, not a later pathname lookup, is its write/readback authority. This avoids treating a substituted per-operation directory as operation-owned. Any name mismatch or pre-publication failure retains an unverified candidate for the durable reconciliation block; it does not authorize pathname-based automatic removal. Successful exclusive publication moves the temporary file to the final target, while a possibly published outcome is classified separately from temporary residue. Deterministic tests must resume through the production substitution path and prove no bytes are written into a replacement and no replacement is removed. The narrow cleanup permission is not an obligation to clean an artifact whose identity cannot be safely established.

The pure core validates/normalizes capture data, computes identity, and renders inert source Markdown. The Obsidian adapter only reads the active staging note and performs the authorized create-only source write, apart from the narrowly approved content-free reconciliation record. The existing native bounded reader caps requests at 128 KiB; M08 must raise that request ceiling to cover its 1,064,960-byte staging bound while retaining descriptor-relative containment and the one-byte overflow sentinel. M07 catalog requests remain capped at 128 KiB, and changed native bytes require fresh M08 artifact qualification without rewriting historical M07 packets. The controller owns ephemeral draft/preview generations and invalidates a plan on active-note edit/switch, paste edit, URL edit, settings/root change, view close, or plugin unload; the reconciliation block is deliberately not ephemeral. No browser process, DOM, cookie, or ChatGPT API access is added to Chat2Vault.

## 5. Fail-closed behavior and privacy

Empty, oversized, malformed, unsupported, or ambiguously marked staging notes fail with content-free diagnostics. A ChatGPT URL, when supplied, must be HTTPS on exact host `chatgpt.com`, with no credentials or non-default port, and path `/c/` followed by a canonical UUID. Chat2Vault discards query and fragment before its own preview, hashing, logging, or source-note persistence; the user sees the normalized URL. Web Clipper may already have written the original URL into its separately controlled staging note, so the companion instructions must tell the user to inspect it before **Add to Obsidian** and remove unwanted query/fragment text from staging notes themselves. A Web Clipper staging note requires that URL; manual paste may omit it. Unsupported URLs cannot be silently relabeled as ChatGPT. If no URL is supplied through manual paste, the missing-provenance warning remains visible in preview and saved note. Any staging-note change after preview, unreadable/unsafe path, incomplete root observation, target collision, or write/readback failure disables save until a fresh valid preview; no fallback write bypasses these checks.

The Web Clipper is a separately installed tool, so Chat2Vault cannot assert control over its internal storage or page-access behavior. The companion instructions disclose that the extension accesses the current page and writes a staging note only after the user's action. Chat2Vault makes no provider or external network request for capture, does not log capture text or personal URLs, and does not persist draft text in plugin settings. The staging note remains in the vault until the user independently removes it; Chat2Vault does not auto-delete it. The saved capture source also remains local Markdown. Existing vault-sync services (including Obsidian Sync, iCloud, or third-party synchronization) may transmit either note independently of Chat2Vault; the no-provider-request claim applies only to Chat2Vault's capture path. Existing M05 requests are not reachable from an M08 capture in this milestone.

## 6. Feasibility and verification gate

Before treating the template as qualified, test the actual official Web Clipper on a **synthetic** ChatGPT-like page and a real ChatGPT page using non-sensitive test content. Record the browser and extension versions, observed clip fields, visible-versus-captured text, creation behavior, and any partial extraction. No real personal conversation belongs in fixtures, logs, screenshots, or the repository. If complete capture cannot be demonstrated, the workflow must retain the `visible-page-unverified` label and offer manual correction/paste; a partial capture is never silently promoted as complete. If the official extension cannot create distinct staging notes without overwriting previous clips, the template path fails its acceptance gate and only the manual fallback may ship until a safe template is found.

Core tests cover malformed markers, partial/unknown properties, invalid Unicode, control characters, hostile Markdown, misleading role labels, URL normalization/allowlist failures, identical-versus-changed capture identity, size boundaries, deterministic rendering, and distinction from export and knowledge-note schemas. Adapter/controller tests cover active-note swaps, edit-after-preview, stale async settlement, unsupported paths, symlinks/physical aliasing, root changes, duplicate no-op, conflicts, failed create/readback, cancellation, zero mutation before explicit save, no staging-note mutation, and no M04/M05/M06 route. Existing M01-M07 suites must remain green.

The completion gate is format, lint, strict typecheck, targeted and full relevant tests, build, boundary/privacy scans, exact candidate review, and macOS x86_64 minimum/current-stable Obsidian runtime rows in disposable vaults. Runtime evidence must show one successful Web Clipper staging-to-source flow and one manual fallback flow with synthetic content, exact created source bytes, zero Chat2Vault provider/network calls, only the approved private temporary and content-free settings-ledger writes outside the explicit source target, separate attribution of Web Clipper's staging write, and no mutation of existing source/knowledge notes. Crash/reload and persistence-failure rows must prove that an unresolved transaction cannot silently restore write eligibility. A Web Clipper limitation is reported as a limitation, not disguised by automated fixtures. Passing the gate does not authorize commit, publication, or release.

## 7. Acceptance ledger

| Requirement            | Acceptance condition                                                                                                                                                          |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fast ChatGPT capture   | A user can create a new official Web Clipper staging note from a ChatGPT conversation page, inspect it, and explicitly preview it in Chat2Vault.                              |
| Manual fallback        | The user can paste bounded ChatGPT text without automatic clipboard read and preview the same capture-source outcome.                                                         |
| Honest scope           | Every preview and saved note says `visible-page-unverified`; no export graph, role, chronology, or completeness claim is invented.                                            |
| Source preservation    | Explicit save creates or no-ops an immutable, source-root-contained capture-source note with stable identity and exact readback; staging and existing notes remain unchanged. |
| Privacy and separation | Chat2Vault makes no provider call for capture; the companion uses no Interpreter; no web capture is eligible for M04/M05/M06 in M08.                                          |
| Compatibility          | The official template behavior is verified on named browser/extension and supported Obsidian host versions, with partial extraction and collision behavior reported honestly. |
