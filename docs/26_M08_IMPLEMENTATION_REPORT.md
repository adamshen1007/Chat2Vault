## Objective and scope

M08 implements ChatGPT-first current-page/text capture as a distinct, immutable `ai-conversation-web-capture` source. It includes strict core normalization and staging contracts, a create-only macOS vault adapter, exact preview authority, manual-paste UI, a content-free durable reconciliation ledger, and forward M08 boundary/runtime gates.

The implemented manual route never reads the clipboard or browser session, never invokes the configured provider, and requires explicit preview and save actions. Runtime staging evidence is intentionally labeled `runtime-harness` / `synthetic-staging-contract`; it does not claim to be an official Web Clipper write.

## Review findings and remediation

- Staging authority now requires the exact active file to remain selected; disappearance without an Obsidian invalidation event blocks save.
- Known publication and uncertain temporary/published effects remain distinct and survive ordinary invalidation through the durable ledger.
- Reconciliation prepare/update/clear uses mutex-protected CAS transaction tokens so concurrent views cannot overwrite or clear another transaction.
- Native temporary identity is canonical, closed, defensively copied, and integrated through parser, adapter, settings persistence, and reload tests.
- The official-template preparation exposed a URL compatibility gap: the original capture validator rejected canonical UUID versions 6-8, including version-8 ChatGPT conversation paths. Synthetic regression tests failed first; the validator now accepts versions 1-8 while retaining the exact host, path, and variant checks.
- Independent R2 review found that a second view could acknowledge a prepared ledger while native publication was active. A service-scope transaction token now rejects acknowledgment until publication settles; a focused red/green test covers the race. Failed uncertainty persistence keeps the durable ledger unresolved.
- Reconciliation guidance now always requires verifying the stored physical source-root device/inode, even when the configured logical path is unchanged. Knowledge-root saves invalidate capture previews. Focused tests cover both corrections; the read-only re-review found no remaining Critical or Important code/asset issue.
- The Web Clipper popup's apparent off-site selection was traced to the documented first-template fallback, not the ChatGPT URL regex. The Product Owner moved a generic fallback above Chat2Vault and observed generic selection on `example.com` and Chat2Vault selection on a synthetic conversation. The exported asset is byte-identical to the tested candidate and has positive/negative contract tests.
- The initial M08 runtime harness inherited a text-patched M05 driver and repeatedly exposed stale DevTools lifecycle coupling. It was replaced with a dedicated M08 driver and explicit shared host primitives. Recovery now uses a fresh port and proves new PID, exact listener owner, target, and renderer session. Failed attempts retain only bounded content-free diagnostics.

- The official Chrome Web Clipper 1.7.1 template created distinct A/B staging notes and the selected-text route reached exact source notes, but unselected `{{content}}` captured unrelated UI text. The shipped asset is limited to selected-text partial capture. A user can manually select the template off-site, so the proposed note and URL still require inspection.

- Settings reconciliation contains no capture text, URL, title, credential, or private diagnostic. Failure packets contain process/lifecycle metadata only.
